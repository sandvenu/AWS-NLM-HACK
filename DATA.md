## Model outputs

Every model output we rely on is a per-item record in
`evidence/records/<run_id>/records.jsonl` (mirrored at
`s3://bb26-p-team07-data-041915167631-use2/evidence/records/<run_id>/`), with:
`model_id`, `adapter_id`, `prompt_sha256` (SHA-256 of the exact chat-templated prompt
string), `output`, `output_sha256`, the parsed answer, the gold answer and the verdict.
Prompts are built by `src/nlm/common.py` (`KNOW_SYS`, `EXEC_SYS`, `messages_for`) and
rendered with the model's own chat template with `enable_thinking=False`; decoding is
greedy. No model output is used as a label anywhere.

## Grader

`rule-based-parser-v1` in `src/nlm/common.py`:
- Knowledge: extract the option letter from `Answer: <letter>` (fallback: a leading
  letter); exact match against the gold letter.
- Execution: take the last `Final answer: <number>`; correct if within 2% relative error
  of the computed answer (also reported: within 5%, the tolerance the Leeds work uses).

No LLM grades anything. `tools/rebuild.py` re-grades every stored output offline.
